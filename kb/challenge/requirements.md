# Challenge requirements, traceable

Source: the challenge page as captured on 2026-11-14 (`spaceapps/challenge/statement.txt`, `spaceapps/challenge/resources.txt`),
https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/?tab=details. Event schedule:
`spaceapps/team/schedule.txt`. Judging criteria and official rules: `spaceapps/rules/event-and-judging.md`.

Every design document, plan item and pitch claim cites the IDs below, so the team can show the judges that each
expectation is met. The challenge text says almost everything is optional ("You may (but are not required to)
consider"); the tiers below are the team's reading of emphasis, not NASA's words. "Core" is what the Objectives
section names as a strong solution; "Considered" is from Potential Considerations; "Optional" is the feature list.

## Core (named in "Objectives" as a strong solution)
| ID | Requirement | Challenge words |
|---|---|---|
| C1 | A functional interactive game or simulation with a clear user interface | "A strong solution might include a functional interactive game or simulation with a clear user interface" |
| C2 | A mission configuration system | "mission configuration system" |
| C3 | Resource management mechanisms | "resource management mechanisms" |
| C4 | Collaboration or multiplayer for up to four participants | "collaboration or multiplayer functionality for up to four participants" |
| C5 | Mission simulation and evaluation | "a mission simulation and evaluation system" |
| C6 | Feedback on performance that rewards good engineering, efficient resources, collaboration and meeting objectives | "provide feedback on mission performance and reward effective engineering decisions, efficient resource management, successful collaboration, and achievement of mission objectives" |
| C7 | The whole mission flow: objective, requirements, spacecraft, instruments, launch vehicle, orbit, and the constraints budget, mass, power, communications, data, lifetime | "define a mission objective, establish mission requirements, design a spacecraft, select scientific instruments, choose a launch vehicle and orbit, and manage key constraints" |
| C8 | Players see how one decision affects other parts of the mission | "seeing how their decisions affect other parts of the mission" |
| C9 | Solo play, and teams of up to four | "participate individually or collaborate with a team of up to four people" |

## Considered (Potential Considerations)
### Game design and experience
| ID | Consideration |
|---|---|
| G1 | Accessible to players with different levels of space knowledge |
| G2 | Single player and team play on the same mission |
| G3 | Team roles, e.g. mission planning, spacecraft design, science, communications, resource management |
| G4 | Clear objectives and feedback: why a mission succeeds or fails |
| G5 | Modify the design and simulate again, many times |
| G6 | Scoring that rewards mission success, scientific value, efficient resources and good decisions |
| G7 | Difficulty levels, mission types or scenarios |

### Mission design
| ID | Consideration |
|---|---|
| M1 | Start by defining a mission objective, before spacecraft and engineering decisions |
| M2 | Every major design decision has a consequence (example: more instruments raise science but also mass, power, cost and data) |
| M3 | There is rarely one perfect solution: different combinations can meet the same objective |
| M4 | Realistic constraints: budget, mass, power, communications capacity, mission lifetime |

### Spacecraft and payload
| ID | Consideration |
|---|---|
| S1 | Components: structure, power systems, batteries, communications, onboard computer, attitude control, instruments |
| S2 | Instruments differ in mass, power, cost, data generation and scientific value |
| S3 | Simple or advanced components depending on difficulty |

### Orbit and launch
| ID | Consideration |
|---|---|
| O1 | Several orbit options, each with its basic characteristics explained |
| O2 | The orbit affects coverage, observation opportunities, communications, lifetime and other requirements |
| O3 | Launch vehicles differ in payload capacity, cost and orbital capability |
| O4 | A check that spacecraft mass and orbit are compatible with the chosen launch vehicle |

### Resource management
| ID | Consideration |
|---|---|
| R1 | The main resources are always clearly displayed |
| R2 | Mass (spacecraft and payload), Power (energy for systems and instruments), Budget (development and operations), Data (generated by instruments), Communications (ability to send data to ground stations), Time (development and operational lifetime) |
| R3 | Identify which resources are most critical to each specific mission |

### Collaboration
| ID | Consideration |
|---|---|
| T1 | In team mode, up to four players work on the same mission |
| T2 | Different roles or responsibilities, with collective decisions |
| T3 | Situations where team members negotiate between competing priorities |
| T4 | The final result depends on how well the team coordinates |

### Educational value
| ID | Consideration |
|---|---|
| E1 | Concepts explained in simple terms, never assuming advanced knowledge |
| E2 | Orbital altitude, payload capacity, power consumption, data rate and communications introduced through the game itself |
| E3 | Short explanations, tutorials, visual indicators or optional learning resources |
| E4 | Teach why a decision affects performance, not only whether it is right or wrong |

## Optional features (the challenge's own list)
| ID | Feature |
|---|---|
| F1 | Multiple mission scenarios with different objectives |
| F2 | Random events or unexpected constraints |
| F3 | Difficulty levels |
| F4 | Realistic or simplified spacecraft models |
| F5 | Interactive spacecraft visualizations |
| F6 | Mission dashboards with real-time resource consumption |
| F7 | Leaderboards or mission rankings |
| F8 | A mission report at the end of each simulation |
| F9 | Save, share and compare mission designs |
| F10 | Cooperative missions for teams of up to four |
| F11 | Competitive scenarios: teams design missions for the same objective |
| F12 | Sandbox mode without predefined constraints |
| F13 | Post-mission analysis explaining why the mission succeeded or failed |

## Resources the challenge points to
Summarized in `spaceapps/challenge/resources.txt`; studied in `kb/research/prior-art.md` (games and tools) and
`kb/domain/` (mission lifecycle, trade-offs). The four mission segments of the NASA document (launch, space, ground,
user) and the JPL Concept Maturity Levels are natural structures for the game's stages.

## Event constraints (local event, `spaceapps/team/schedule.txt`)

- Teams present at 11:00 AM: 5 minutes of pitch, 2 minutes of questions.
- The day is not written in the notes; the team must confirm it (see `kb/decisions.md`).
